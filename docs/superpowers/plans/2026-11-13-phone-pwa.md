# Phone PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone on the home Wi-Fi pairs with the hub through a QR code and shows the hub page full screen as an installable, read-only PWA.

**Architecture:** A new `hub/lan.mjs` holds the LAN rules (config, token, Host allow-list, route guard). `hub.mjs` calls it first in `handle` and binds to the LAN address when enabled. `web/phone.html` reuses `hub_page.js` in a read-only mode and adds the manifest, wake lock and an offline banner.

**Tech Stack:** Node >= 18 standard library, `node:test`, plain ES modules in the browser.

**Spec:** `docs/superpowers/specs/2026-11-13-phone-pwa-design.md`

## Global Constraints

- Default stays loopback: without `lan.enabled` the hub binds `127.0.0.1` and behaves as today (existing tests unchanged).
- Standard library only in `hub/`; no CORS; the hub imports nothing from a device; `core_standalone` stays green.
- Remote clients may call only `GET /phone`, `/phone.html`, `/manifest.webmanifest`, `/state`, `/events`, `/health` and the static files and icons the page loads; every other route answers `403`.
- Cookie `agentsdash_token`: HttpOnly, SameSite=Strict. Token: 128 bits, file `~/.agentsdash/lan-token`, never in `/state`, `/health` or logs. Compare with `crypto.timingSafeEqual`.
- Protocol stays 2. Raise `version` in `hub/package.json`.
- Test command: `node --test hub/test/*.test.mjs` (no directory argument).
- Code comments, docs and on-screen text in English.

## Review Focus

- Token sent as `?t=` on a route other than `/pair`: must not authenticate (test in Task 2).
- `Host: evil.example` with a valid cookie from a remote address: `403` (Task 2).
- `HEAD`/`OPTIONS` or `POST /event` from a remote address with a valid cookie: `403` (Task 2).
- IPv4-mapped loopback (`::ffff:127.0.0.1`) counts as loopback (Task 1).
- `lan-token` file missing, empty or unreadable: a new token is created, no crash (Task 1).
- Event stream drops mid-session: banner shows, reconnect delay grows from 1 s to 10 s and resets on success (Task 3).

### Task 1: LAN rules module

**Files:**
- Create: `hub/lan.mjs`
- Modify: `hub/config.mjs` (return `lan`)
- Test: `hub/test/lan.test.mjs`, `hub/test/config.test.mjs` (add cases if a config test file exists, else put them in `lan.test.mjs`)

**Interfaces:**
- Produces:
  - `loadConfig(...)` result gains `lan: { enabled: boolean, bind: string }`. Default `{ enabled: false, bind: '0.0.0.0' }`. Env `AGENTSDASH_LAN=1` forces `enabled: true`; `bind` is kept only when it is a string.
  - `isLoopback(address: string): boolean` true for `127.0.0.1`, `::1`, `::ffff:127.0.0.1`.
  - `loadOrCreateToken(file: string): string` 32 hex chars; creates parent dir and the file (mode 0o600) when missing or empty.
  - `tokenMatches(given: string | undefined, token: string): boolean` via `timingSafeEqual`, false on length mismatch.
  - `lanHosts(port: number, extra?: string[]): Set<string>` loopback names plus each private IPv4 of `os.networkInterfaces()` plus `os.hostname()`, each as `name:port`.
  - `parseCookie(header: string | undefined, name: string): string | undefined`.
  - `REMOTE_ROUTES: Set<string>` of `"METHOD /path"` for the three static entries plus `GET /state`, `GET /events`, `GET /health`.
  - `isRemoteStatic(urlPath: string): boolean` true for files the page loads (`.js`, `.css`, `.svg`, `.png`, `.webmanifest` under `web/` and icon URLs); false for `/api`-like or unknown paths.

### Task 2: Guard, pairing routes and LAN bind in the hub

**Files:**
- Modify: `hub/hub.mjs` (`startHub` opts, `handle` at the Host/Origin check near line 187, `server.listen` near line 408, MIME map line 55)
- Test: `hub/test/hub_lan.test.mjs`

**Interfaces:**
- Consumes: everything `lan.mjs` produces (Task 1).
- Produces:
  - `startHub` option `lan?: { enabled, bind, tokenFile?, treatAllAsRemote?, hosts? }`; default comes from `config.lan`. `treatAllAsRemote` and `hosts` exist for tests only (a test client connects from loopback).
  - `GET /pair?t=<token>`: valid token gives `302` to `/phone` with `Set-Cookie: agentsdash_token=<token>; HttpOnly; SameSite=Strict; Path=/; Max-Age=31536000`; invalid gives `401`.
  - `GET /pair-info` (loopback only; `403` for remote): `{ url: "http://<first private ip>:<port>/pair?t=<token>" }`, or `{ url: null }` when LAN is disabled or no private address exists.
  - `GET /phone` serves `web/phone.html`; `.webmanifest` maps to `application/manifest+json` in `MIME`.
  - Binding: `host` becomes `lan.bind` when `lan.enabled`, else `127.0.0.1`.
  - Guard order in `handle`: remote? (not loopback and `lan.enabled`, or `treatAllAsRemote`) then Host in `lanHosts`, Origin same set, then `/pair` handling, then cookie check (`401`), then route allow-list (`403`), then the normal switch. Loopback requests keep the exact current code path.

### Task 3: The phone page

**Files:**
- Create: `hub/web/phone.html`, `hub/web/phone.js`, `hub/web/manifest.webmanifest`, `hub/web/phone-192.png`, `hub/web/phone-512.png`, `hub/web/phone-180.png` (Apple touch icon)
- Modify: `hub/web/hub_page.js` (read-only switch), `hub/web/hub.css` (mobile rules at 390 px width)
- Test: `hub/test/phone_page.test.mjs`

**Interfaces:**
- Consumes: `GET /phone` route and `webmanifest` MIME (Task 2).
- Produces:
  - `phone.html` links `/manifest.webmanifest`, sets `theme-color`, `apple-mobile-web-app-capable`, `apple-touch-icon`, loads `/hub_page.js` with `document.documentElement.dataset.mode = 'phone'` set before it, then `/phone.js`.
  - In phone mode `hub_page.js` does not mount the footer (no settings, themes, sound controls) and sends no POST.
  - `phone.js` exports nothing; it (a) requests `navigator.wakeLock.request('screen')` after the first `pointerdown` and again on `visibilitychange` to visible, silent when unsupported; (b) shows `#hub-down` banner "Hub unreachable, retrying" when the event stream errors; (c) reconnect delay 1 s doubling to 10 s, reset after a message. Put the delay logic in a pure `nextDelay(previous: number): number` exported from `hub/web/reconnect.js` so it can be unit tested.
  - `manifest.webmanifest`: `name` "Agents Dash", `short_name` "Agents", `start_url` "/phone", `display` "standalone", `background_color` and `theme_color` taken from `hub.css`, icons 192 and 512 PNG. Icons: draw a simple generated glyph (script in `hub/tools/make_phone_icons.mjs` writing PNGs with `node:zlib`; committed output).
