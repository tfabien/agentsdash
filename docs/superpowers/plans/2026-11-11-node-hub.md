# Node.js hub and plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Node.js hub that shows the agent standup in a browser (with or without the ESP32, over Wi-Fi or USB), and a Claude Code plugin written in Node.js that replaces the Python scripts.

**Architecture:** Hooks (`notify.mjs`) always POST v2 events to a local hub (`127.0.0.1:8765`). The hub holds the state (`model.mjs`, a port of `model.cpp`), serves a web page over SSE, polls the plan quotas, and relays to a gadget over HTTP or serial. The wire format is unchanged, so hub and gadget are interchangeable.

**Tech Stack:** Node >= 18 (developed on 24.18), ES modules, `node:test`, no npm dependency except `serialport` (USB mode only).

**Spec:** `docs/superpowers/specs/2026-11-11-node-hub-design.md`

## Global Constraints

- Node >= 18, ES modules (`.mjs`), no build step, no npm dependency except `serialport` (optional, USB mode).
- Hub binds `127.0.0.1` only, default port 8765, no authentication.
- Wire format: `agent-gadget/ARCHITECTURE.md` section "Wire format" (`POST /event` v2, `POST /usage`, `GET /state`, `POST /select`, `POST /reset`). Events stay ASCII.
- State rules identical to `agent-gadget/esp32_agent_gadget/model.cpp`: 5 sessions, 12 sub-agents each, done TTL 120 s, stale TTL 600 s, status-line context wins for 120 s, manual selection hold 30 s.
- Hooks never print to stdout, never throw, give up after 1.5 s, exit 0.
- Env options kept: `CLAUDE_GADGET_HOST`, `CLAUDE_GADGET_MASK`, `CLAUDE_GADGET_DRY_RUN`, `CLAUDE_GADGET_DUMP`, `CLAUDE_GADGET_QUOTAS`. `CLAUDE_GADGET_PROTOCOL` is dropped.
- Config file `~/.claude/agent-gadget.json`: `host`, `relay` (`{"mode":"none"|"http"|"serial","host","port"}`), `quotas`, `context_window`.
- Code comments, docs and on-screen text in English.
- **The plugin is read live from this working tree** (`agent-gadget@agent-gadget-local`): `hooks.json` keeps calling the Python scripts until Task 7. A broken hook script breaks every Claude session.

## Review Focus

- Hub not running and cannot start (port busy, `node` missing): the hook still exits 0 within 1.5 s and prints nothing. Test in Task 4.
- Two hooks fire at the same instant while the hub is down: only one hub process survives (second bind fails, exits quietly). Test in Task 4.
- Event with unknown fields, empty `session`, or a non-ASCII `cmd`: the hub answers 400 or sanitizes, never crashes. Test in Task 1 and 2.
- A sixth session or a thirteenth sub-agent: dropped or reported as overflow like the firmware, no crash. Test in Task 1.
- Browser closes and reopens, or hub restarts mid-session: the next event repairs state (each event carries full agent state). Test in Task 2.
- Port 8765 taken by another program: hub exits with a clear stderr line, the hook gives up silently. Test in Task 4.
