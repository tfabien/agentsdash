# Hub drives the device screen

Status: draft, 2026-11-12. Goal: the web page and the Artillery X3 screen share one UI implementation, so a UI change is made once.

## Problem

The UI exists twice. `plugin/hub/web/screen.js` (layout, state, hit tests) is a hand port of the firmware files
`display_hmi.cpp` (929 lines), `layout.cpp` (75), `ui_state.cpp` (149), and `model.cpp` (611) is ported to `plugin/hub/model.mjs`.
`CLAUDE.md` asks to keep them in step. Every UI change costs two edits, one of them in C++ with a flash cycle.

## Constraint found while prototyping

The screen is a TJC serial HMI (480x272) behind a 115200 baud UART. It has no pixel write command: it runs ASCII commands
(`fill`, `cirs`, `xstr`, `pic`, `picq`) against fonts and pictures stored in `agent-gadget.tft`.
A raw frame is 261 120 B, about 23 s at 11.5 KB/s, so pushing bitmaps from the hub is not possible.
(A prototype showed the hub can render the scenes to RGB565 in 1 to 2.5 ms with `@napi-rs/canvas`, useful for the page only.)

## Design

The hub computes the TJC command list and the ESP32 relays it.

1. `plugin/hub/tjc_screen.mjs` implements the `screen` object that `screen.js` already draws on
   (`begin`, `measure`, `pic`, `erase`, `fill`, `rect`, `circle`, `ring`, `line`, `text`) and records TJC commands instead of canvas calls.
   `screen.js` does not change, so the layout stays single-sourced.
2. `measure` uses the TJC font widths (`firmware/font_metrics.h`, generated by `tools/make_font_metrics.py`) exported to a JSON table the hub reads.
   Text is ASCII only on the device, so the hub folds accents and unknown characters before drawing.
3. The hub keeps the last command list per region and sends only the commands that differ (what `display_hmi.cpp` does today with its change tracking).
   A full redraw happens on connect, after a `.tft` upload, and on request.
4. Transport: new route `POST /hmi` on the ESP32 (body: command lines, binary-safe, `FF FF FF` added by the firmware), over the existing HTTP relay
   and the serial relay. Commands go to the UART queue in `hmi_uart.cpp` unchanged. Requests stay small (a diff is tens of bytes to 2 KB).
5. Touch: the firmware keeps reading `67 xh xl yh yl st` and posts `{x, y, press}` to the hub (`POST /touch` on the hub, or a field of the response to the next `/hmi`).
   The hub runs `hitTest` from `screen.js` and updates its UI state (selected tab, plan step preview). The page and the device then share the same state.
6. Firmware keeps: Wi-Fi setup portal, OTA (`/update`, `/tft`), baud switch, buzzer, clock fallback, `UART` queue and pacing.
   Firmware drops: `display_hmi.cpp` drawing logic, `layout.cpp`, `ui_state.cpp`, and the agent model in `model.cpp` once the hub is the only source.

## Behavior without a hub

The device shows the message "no hub" plus its IP after 30 s without a command. The direct device-IP host mode of the plugin (events straight to the gadget) is removed.
This is the main loss. Alternative if it matters: keep the old firmware UI as a fallback build (`-DLEGACY_UI`), frozen and not maintained.

## Steps

1. `tjc_screen.mjs` plus tests: command list for each scene of `scenes.js`, compared against a recording of today's firmware output (golden files from `/debug/stats` or `hmi_uart` capture).
2. Diff engine and region tracking, with a test for "only changed regions are sent".
3. Firmware `POST /hmi` and `POST /touch` path next to the existing UI (feature flag), tested on the real gadget with `scripts/scenario.py`.
4. Switch the relay to the new path, then delete the firmware UI and the model port.
5. Update `CLAUDE.md` files and `INSTALL.md`.

## Open questions

- `ring` (context ring) has no TJC primitive: today's firmware draws it with `cirs` and pictures, or segments. Decide the same rendering in `tjc_screen.mjs`.
- Pacing: the UART runs at 11.5 KB/s, a full redraw of 1 KB to 3 KB takes 100 to 300 ms. Measure with `/debug/stats` (`est_ms`) and set a command budget per tick.
- Robots blink and bob: today the firmware animates locally at fixed times. Hub-driven animation at 2 to 4 Hz costs Wi-Fi round trips, so keep a tiny local blink loop or drop the bob on the device.
- Hub restart or Wi-Fi drop mid-diff: the firmware needs an "unknown state" flag that forces a full redraw on the next command.
